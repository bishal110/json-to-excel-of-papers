## SECTION 6: DIAGNOSTIC LOGIC


### P32-D01: PCA persistent alarm

**Rule ID:** P32-D01

**IF:** More than 12 out-of-control minutes in 1440-minute day

**AND:** Condition occurs on two consecutive days

**THEN:** Flag serious abnormality for engineering inspection.

**Engineering Explanation:** Source multiplier 3×~4 chance exceedances; local validation required.

## SECTION 8: MACHINE LEARNING / AI CONTENT


**Model Type:** Per-ESP PCA T² versus XGBoost motor-vibration regression residual with SPC aggregation.

**Inputs:** Six failed ESPs>1 year history; initial windows grown 20,000 min to 210,000 min; preferred 180,000 min~125 days; sequential 80/20 within-window validation for regression.

**Outputs:** Abnormal minute/day and persistent failure advisory.

**Accuracy:** Table 1 PCA false alarms 1, 4, 0, 3, 5; leads 14, 7, 1, 1, 3 days (first 5). Nonlinear false alarms 1, 11, 12, 10, 6; leads 14, 41, 10,120, 13. Sixth poor-quality well: PCA19 false/2 days, nonlinear 2 false/327 days, excluded from averages. No classification accuracy or independent nonfailure cohort.

**Advantages:** Chronological per-well construction and explicit alarm persistence tradeoff.

**Limitations:** Six failed wells only; parameter selection retrospective; no fleet rate denominator; two-day persistence delays fast faults; real-power proxy I×V omits three-phase power factor/efficiency.

**Can it be implemented using only Avalon Data / Production Test Data / Surface Pressure Data?:** PCA needs pressure/rate/temperature; residual method requires measured vibration at scoring, not just surface predictors. Cannot calculate residual after losing vibration sensor.

**Complexity:** Medium
